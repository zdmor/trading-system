# Alpha Trader 方法论附录

> 来源: Mike Bellafiore, SMB Capital 创始人
> 核心: 交易是可训练的，不是天赋。流程 > 结果。每日复盘是成长的原子单位。
> 用途: 本文件不是书摘，是从中提取可用于本项目的框架。

## 1. 三个 Tier（你当前在哪）

| Tier | 名称 | 定义 | 你系统的对应 |
|------|------|------|-------------|
| Tier 1 | **Process** | 每天固定流程：几点做什么、出了信号怎么办 | project_plan.md + 每日任务流程 |
| Tier 2 | **Strategy** | 选什么股、参数怎么设、什么时候买卖 | system_philosophy.md + scanner 参数 |
| Tier 3 | **Psychology** | 执行时的恐惧/贪婪/拖延 | nightly 晚间问题 + 复盘 |

Bellafiore 的结论：**90% 的新交易者死在 Tier 1，不是 Tier 2。** 策略再好，没有纪律的执行等于零。

你的项目目前已定 Tier 1（项目计划 + 每日检查），Tier 2（白皮书 + 需求），Tier 3（每晚晚間問題）。

## 2. Process over Outcome（流程重于结果）

**这是整个方法论的核心。**

| 情况 | 传统看法 | Alpha Trader 看法 |
|------|---------|-----------------|
| 赚钱但没按系统来 | "赚钱了，不错" | **坏交易**。流程违规，下次可能亏大的 |
| 亏钱但完全按系统来 | "亏了，系统有问题" | **好交易**。流程正确，结果是概率的一部分 |
| 赚钱且按系统来 | "正常" | 期望的结果，持续做 |
| 亏钱且没按系统来 | "糟糕" | 双输，需要复盘流程为何没执行 |

**在你的系统中的应用：**

| 场景 | 等级 |
|------|------|
| scanner 跑出信号，按 checklist 检查后开仓，最后亏损 | 好交易。不追责，不因亏钱改参数 |
| 没等 scanner 跑完就手动开了仓，最后赚了 | 坏交易。不是因为赚钱就对 |
| 红灯+Markdown 不开新仓，错过一只大涨 | 好交易。流程正确，错过是常态 |
| 红灯+Markdown 觉得"这次不一样"开了仓，亏了 | 双输。需复盘为什么没执行 |

**把 Process over Outcome 写进你的复盘：** 每次复盘先评这个，再看盈亏。

```
做对了什么:
- 

做错了什么:
-

- 

流程评级 (✅ 按系统 / ⚠️ 有偏离 / ❌ 违规):
```

**关键：** "分数"是比昨天的自己，不是比市场。亏钱了但比昨天多执行了一个流程步骤，分数应该比昨天高。

## 4. Five P's — 交易前的最后检查

SMB 每个交易员开仓前必过：

```
P1. price — 价格在正确的位置吗？（关键位/突破位/支撑位）
P2. pattern — 图形结构确认了吗？
P3. position sizing — 这单用多大仓位，为什么？
P4. preparation — 进场后的预案（触发止损怎么办？到目标位怎么办？）
P5. psychology — 我现在的心态能执行第4条吗？
```

你的 pre_buy_checklist.py 已经在做 P1-P4（结构/信号/仓位/止损）。**加了 P5 就齐了。**

建议加的字段：在 print_report() 中加一行 `psychology_check: pass/fail`，需要你手动填。

## 5. Bellafiore 对你的系统最直接的提醒

**"系统越复杂，执行越难。执行越难，你越不会用它。"**

你白皮书里有 8 因子 + 2D 门控 + 4 种止损 + ATR 仓位 + CAN SLIM 卖法。Bellafiore 会说：系统很好，但你的每日流程能不能坚持用？

衡量标准不是"参数最优"，而是**连续 30 天是否每天都跑了 Scanner + 填了复盘记录**。如果能做到，一个月后系统再烂也比大多数散户强。

## 6. 你的训练日程（2026-06-03 起）

**每日流程（固化到生物钟）：**

```
8:30  ── python scanner.py（不开电脑不开始一天）
     ── 看输出：信号数/红绿灯/大盘阶段
     ── 有信号 → python pre_buy_checklist.py
     ── 要开仓 → 过 5 P's（必须填完才能下单）
```

**每周一：** Process Score 评估（连续几天按流程走了？）
**每周五：** 本周系统有什么问题，下周修什么。

**模板位置：** `recaps/TEMPLATE.md`
**复盘记录：** `recaps/YYYY-MM-DD.md`

**前 7 天的唯一目标：连续 7 天不间断跑完流程。** 不调参数，不改策略，只看能不能坚持。能做到这个，后面才谈得上优化。
